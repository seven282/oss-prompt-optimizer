# 21 个子类 × 完整优化示例

> 从一句粗糙指令到一个专业、可直接交给 AI 执行的提示词。
> 按「角色 + 任务 + 背景 + 格式」四段结构输出。

---

## 🐛 Code 类（5 个）

### 1. code-bugfix（Bug 修复）

**输入**：`修复 cache.ts 里的 bug`

**优化输出**：

```
作为资深 TypeScript 工程师，精通类型系统与缓存模块设计，先保证修复正确再考虑优化。
定位并最小化修复 @src/cache.ts 中的错误：静态分析定位每个错误并列出触发条件，
应用最小修复保持导出接口与缓存语义不变，标注每个改动，运行 tsc --noEmit 及相关测试。
未给出具体错误信息或环境时，根因不明时用最保守修复并说明推断依据。
① 根因分析（简短要点）② 改动（前后对比）③ 测试结果；附可运行的完整代码片段。
```

---

### 2. code-feature（新功能开发）

**输入**：`做一个用户登录功能`

**优化输出**：

```
作为资深全栈工程师，擅长安全认证与会话管理，优先保证安全再优化体验。
实现用户登录功能：明确需求边界（邮箱/密码/第三方 OAuth）→ 设计认证流程（JWT/Session）→
实现后端接口与前端表单 → 写测试覆盖正常/异常路径 → 验证安全（防暴力破解、CSRF）。
说明技术栈、已有用户表结构、部署环境。
完整可运行的代码 + API 文档 + 使用示例，附必要的错误处理与输入校验。
```

---

### 3. code-refactor（重构）

**输入**：`重构这个函数，太乱了`

**优化输出**：

```
作为资深工程师，擅长识别代码异味并保持行为等价地重构。
重构给定函数：识别代码异味（重复/嵌套过深/命名不清）→ 保持外部行为完全不变 →
改进结构与可读性 → 确认所有测试通过。
说明函数所在文件与用途；保持原有接口签名与副作用不变。
① 现状问题列表 ② 重构策略 ③ 重构前后对比 ④ 行为不变说明 + 测试结果。
```

---

### 4. code-review（代码审查）

**输入**：`帮我 review 一下这段代码`

**优化输出**：

```
作为资深代码审查者，逐条检查正确性、可读性、安全性与性能。
审查给定代码：按正确性 → 可读性 → 安全性 → 性能 → 测试覆盖逐项检查，
列出每个问题的严重度（Critical/High/Medium/Low）、位置与修复建议。
说明代码的业务上下文与技术栈；阻塞问题优先标注。
问题清单（严重度 + 位置 + 建议）+ 汇总评价。
```

### 5. code-script（脚本/工具）

**输入**：`写个脚本批量重命名文件`

**优化输出**：

```
作为资深 Python 工程师，擅长编写健壮的文件操作脚本。
编写批量重命名脚本：定义命名规则，处理异常与冲突，记录执行日志。
输入目录与命名规则；不修改原文件（先 dry-run）；说明依赖与运行方式。
直接可运行的 .py 文件 + 顶部使用说明（依赖、运行命令、示例输出）。
```

## 核心规律

**优化 = 补全「谁做 + 做什么 + 为什么 + 怎么交付」四要素**

| 类别 | 核心侧重 |
|---|---|
| **Code** | 可运行性、测试覆盖、安全、最小改动 |
| **Writing** | 身份定位、受众语气、文体规范、结构完整 |
| **Analysis** | 结论先行、数据支撑、来源引用、局限声明 |
| **Ops** | 步骤可逆、回滚方案、环境验证、执行清单 |
